# 🕵️ Relatório Forense: MobileMakers (Deploy & Rebranding)

**Data:** 2026-05-11  
**Investigador:** Antigravity (GSD Orchestrator)  
**Status da Investigação:** CONCLUÍDA

---

## 🔍 Resumo dos Achados

O projeto enfrentou um "bloqueio em cascata" causado por uma discrepância de nomes de variáveis de ambiente entre o código e a configuração da Vercel/Supabase, agravado por regras estritas de build do Next.js (ESLint).

---

## 🚨 Anomalias Detectadas

### 1. Falha Persistente de Build (Supabase Connection)
- **Evidência:** Logs da Vercel indicando `Your project's URL and Key are required`.
- **Causa Raiz:** O código herdado utilizava `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, enquanto a configuração injetada pelo usuário e o padrão do Supabase esperavam `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- **Impacto:** Todas as rotas que instanciam o cliente do Supabase quebravam durante a pré-renderização estática.

### 2. Erro 404: NOT_FOUND na Vercel
- **Evidência:** Screenshot do usuário mostrando página de erro de infraestrutura.
- **Causa Raiz:** Como nenhum build conseguiu completar com sucesso (devido à Anomalia 1), a Vercel não tinha uma versão funcional para servir no domínio principal. O domínio apontava para o "nada".

### 3. Bloqueio de Build por Linter (ESLint)
- **Evidência:** Execução de `npm run lint` revelou 10 erros fatais.
- **Causa Raiz:** O Next.js (via Turbo) por padrão trata avisos como erros de build. Avisos de "variáveis não utilizadas" no middleware e "caracteres não escapados" impediam o progresso mesmo após a correção das chaves.

### 4. Conflito de Ambiente Local
- **Evidência:** `.env.local` continha nomes de variáveis obsoletos e um valor de chave que parecia não ser do Supabase (`sb_publishable...`).
- **Causa Raiz:** O ambiente local estava dessincronizado com a nova estrutura de dados real.

---

## 🛠️ Ações Corretivas Tomadas

1. **Sincronização de Chaves:** Todos os utilitários (`client.ts`, `server.ts`, `middleware.ts`) foram atualizados para usar `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
2. **Blindagem de Build:** Adicionado `force-dynamic` em páginas críticas e fallback de string vazia no middleware para evitar crash durante o build estático.
3. **Limpeza de Linter:** Iniciada a correção dos 10 erros de linting (types, links, entidades React) para permitir que o build complete.
4. **Setup Local:** Correção do arquivo `.env.local` para espelhar a configuração de produção.

---

## 📋 Recomendações

1. **Build de Confirmação:** É imperativo que os 10 erros de linting sejam corrigidos ANTES do próximo push.
2. **Refresh de Tabs:** O usuário deve fechar as abas do VS Code que apontam para a pasta antiga `antigravity/` para evitar confusão de cache.
3. **Redeploy Limpo:** Após as correções de lint, disparar um redeploy na Vercel com o cache limpo.
